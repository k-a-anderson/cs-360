CS 360 Portfolio Artifact Reflection – Weight Tracker App
Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

The Weight Tracker app was designed to allow users to log their daily weight, set a goal weight, and track progress over time in a simple and private way. The main goal of the app was to support users who want a straightforward method for monitoring weight without the complexity of larger fitness platforms. The app addresses the user need for consistency, visibility of progress, and optional motivation through notifications when a goal is reached.

What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?

The app includes a login screen, a weight history screen with a grid display, and a notifications screen for goal and SMS settings. These screens were designed to follow a logical flow, allowing users to complete tasks such as logging a weight or managing notifications with minimal steps. The UI design focused on clear labels, simple layouts, and intuitive navigation, which helped reduce confusion and made the app easy to use. The designs were successful because they aligned closely with user expectations and prioritized clarity over unnecessary features.

How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?

The app was developed using an incremental approach, starting with database setup and basic navigation before adding more advanced functionality. Breaking the project into smaller components made it easier to test, debug, and refine individual features. Clear naming conventions, in-line comments, and reusable helper classes were used to keep the code organized. These strategies can be applied in future projects to improve maintainability and reduce development errors.

How did you test to ensure your code was functional? Why is this process important, and what did it reveal?

Testing was performed using the Android Emulator to verify screen navigation, database persistence, permission handling, and CRUD operations. This process was important because it helped identify layout issues, logic errors, and permission-related edge cases early in development. Testing revealed areas where UI spacing and activity behavior needed adjustment, allowing those issues to be corrected before final submission.

Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?

One challenge involved implementing SMS notifications while ensuring the app continued to function if permission was denied. This required designing conditional logic that respected user choices without breaking core functionality. Another challenge was balancing system UI elements with custom layouts to maintain a consistent visual hierarchy. Overcoming these challenges required research, experimentation, and iterative refinement.

In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?

The database-driven weight history screen best demonstrates the skills developed during this project. Implementing full create, read, update, and delete functionality within a grid layout, while maintaining persistent data storage, reflects a strong understanding of Android app architecture. The integration of user input, database logic, and UI updates highlights practical experience in building a functional, user-centered mobile application.
